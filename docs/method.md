# 方法与可信度

本项目先从声音得到候选击球时刻，再用画面人工确认；把近端球员的骨骼脚部位置映射到场地坐标。分析输出用于辅助教练观察，不是完整的球轨迹重建或自动动作评分。

| 阶段 | 做什么 | 输出与人工介入 |
|---|---|---|
| 00 质检 | 检查画面宽度、帧率、时长和音轨 | 不满足输入门槛则退出；外置音频可补充音轨 |
| 01 预处理 | 导出单声道音频并读取视频信息 | 音频与视频元数据 |
| 02 骨骼 | MediaPipe Tasks 逐帧识别，以髋部画面位置排序区分人物 | 骨骼坐标表、骨骼叠加视频；身份排序可能误判 |
| 03 场地标定 | 找白线候选交点，建立像素到场地的单应变换 | **复核①**：人工对应标准点，预览投影线并保存 |
| 04 场地坐标 | 与参考画面匹配来补偿机位晃动，映射脚部位置，拒绝异常定位 | 每帧场地坐标与定位统计 |
| 05 事件检测 | 高频音频能量寻找击球候选，并按强候选的间隔切分回合 | 候选表、回合区间、复核用放大帧；不是最终击球真值 |
| 06 逐拍复核 | 标注本方、对手、非击球或未判断，可填动作类型与备注 | **复核②**：人工完成后继续流水线 |
| 07 指标与图表 | 平滑位置，估计中心、回位、准备时间及分段压力 | 逐拍明细、指标汇总、跑位和时间线图 |
| 08 报告素材 | 汇集元数据、标定情况、指标、逐拍明细和图表 | 结构化报告输入；分析报告及训练计划另行人工撰写 |

场地标定应至少选 4 点，同时包含靠网和靠底线的点；平均误差应小于 0.10 米，并检查未参与标定的场地线是否也重合。不得把交点拟合误差当成整体追踪精度。输入宽度至少 1280，帧率至少 25fps，固定后方高机位且带声音更适合分析；操作指南建议 60fps，源码在低于 50fps 时提醒。

逐拍复核页面支持「1 本方、2 对手、3 非击球、0 未判断」，J/K 切换候选，P 播放局部视频。拿不准保留问号，不猜。应先复核完整回合，尤其是对手击球：源码在缺少对手标签时会取两次本方击球之间最强的候选声作估计，准备时间的可信度会因此下降。

## 指标可信度规则

以下规则来自输入操作指南第六节，适用范围仍限于已经验证的拍摄条件。

| 指标 | 使用规则 |
|---|---|
| 场地坐标、中心位置、回位时间、准备时间、分段压力 | 可用，但应说明定位成功率、复核完成度和拍摄条件 |
| 击球点左右计数 | 靠近中线会随定位及处理方式变动；报告只保留稳定的定性结论 |
| 总跑动距离 | 只报范围，展示不同平滑窗口结果，不能挑一个数字当精确值 |
| 关键拍动作 | 只做定性描述；挥拍瞬间手腕经常缺失，需看原画面 |
| 启动反应时间、背后机位膝角 | 禁用，当前测不准且左右腿可能认反 |

`config.toml` 的禁用项包含反应时间、背后膝角及精确总距离。源码仍输出左右计数和多种平滑距离，人工写报告时必须应用以上规则。每条结论标明依据（数据或画面）与置信度（高、中、低）；不能从一个回合推断长期习惯，看不清得失分就明确写未知。

## 对比样片

`compare/render_compare.py` 独立于分析流水线。输入是人工选定的业余、高手慢放和全身片段，配置里提供触球时刻、窗口和裁切区域。它将触球前后映射到统一时间轴，识别骨骼、围绕人体裁切，渲染单人往复与同步并排片段。触球处有短暂停留，以便观察。

渲染算法、阈值及原布局未在公开整理时调整。全身片段的采样起点、裁切和触球帧仍为固定样片设置，详见局限。示例配置仅演示字段结构，不包含可播放素材，也不代表自动挑动作或通用动作匹配已经实现。
